Rig song format, version 1

A song is one JSON object. Load it with Menu › Load song JSON. If the page is self-hosted you can also put it in a link: #j= + URL-encoded JSON, or #p= + base64url deflate-raw. Every field is optional; missing values get sensible defaults, and the loader reports warnings instead of failing.

Link to a song

Append the song to the page address: #z + base32 (alphabet a-z2-7, lower case, no padding) of the raw-DEFLATE-compressed JSON. It uses only letters and digits, the only kind of hash some viewers (such as the Claude artifact page) pass on; very long links can still be cut, in which case share the JSON instead. Python: c = zlib.compressobj(9, zlib.DEFLATED, -15); url = page + "#z" + base64.b32encode(c.compress(raw) + c.flush()).decode().lower().rstrip("="). On a self-hosted copy, #j= + encodeURIComponent(JSON) also works with no compression. Menu › Copy share link makes a #z link for the current song.

Samples

The sampler and grain modules play samples by name. Built-in samples the rig renders itself: @break (a 1-bar breakbeat at 168 bpm, ideal for slices: 16) and @chord (a 4-second D minor 9 pad). Other names refer to audio the user has loaded into their browser, so ask which sample names they have (the AI brief from Menu lists them) or tell them which file to load and what to call it. Slicing: with slices: N the note root plays slice 1, root+1 plays slice 2, and so on. Use mode:"oneshot" for drums. Wire both channels: "smp -> out", "smp.r -> out.r".

Wires

"from.port -> to.port". Ports can be left out: the output defaults to the first output (usually out) and the input to the first input. Inputs add up. Feedback loops are allowed (one-sample delay). Signals are plain numbers: audio is about ±1; pitch/cut/time/rate/drive inputs take octaves; pm takes cycles; cv/amp multiply.

Knobs as inputs: a wire can also go into any knob or menu of a module ("lfo -> osc.level", "seq -> osc.wave", "env -> sub1.decay" for a sub-patch box knob). The signal turns the knob from where it is set: +1 = its whole range up, −1 = down, along the knob's own curve (so on a Hz or time knob, steps are musical); a menu steps through its choices. List knobs you want shown as sockets in the module's inputs, e.g. "osc": {"type": "osc", "inputs": ["level", "wave"]} (wired knobs show anyway). Each voice gets its own copy, so per-note modulation works.

Macros

A sound (inst) or a custom effect (type: "graph") can carry macros: big knobs that each turn several knobs inside it at once, like an Ableton rack. [{name, value, to: [{node, param, min, max}]}]: value 0–1; at 0 each knob sits at its min, at 1 at its max, following the knob's own curve (Hz and times move musically); max below min turns it the other way. A menu's min and max are its choices, by name or number. A target can be a sub-patch box knob. Left-out min/max mean the knob's whole range, and "node.param" is short for a whole-range target. Paths: track/inst/macro/0, track/fx/1/macro/0, so macros automate, lock, take MIDI controllers and modulation lanes like any knob. In the page: double-tap a knob in the patch or the knob list › Add to a macro; macros show on the Sound tab and on the effect card.

Patterns

{len, div, steps} or {len, div, notes}. div = steps per beat (4 = 16ths, 2 = 8ths, 3 = 8th triplets, 1 = quarters). Patterns of different lengths drift against each other (polymeter).

steps string: one token per step, separated by spaces: . rest, - tie (extends the previous note), a note C3 F#2 Bb4, a chord C3+Eb3+G3, x = the track's default note, X accent, o ghost. Suffixes: ! accent, ~ soft, ? 50% chance, ^ slide into this note (mono tracks). Drum shorthand without spaces works too: "x...x..X..x.o.x.". A plain string is accepted as a whole pattern. | is ignored, so you can use it to mark bars.

Step locks (parameter locks): a token can carry values in braces, C3{fx/0/cut=300,send/A=0.8}, and a note object can carry set: {"fx/0/cut": 300}. Paths starting with inst/ fx/ send/ mix/ gen/ refer to the same track; anything else is absolute ("chords/fx/1/fb", "bpm"). A lock applies when the note plays and snaps back to the knob value at the next note on that track without the lock.

Stochastic patterns: {gen: {...}} replaces steps. Each bar the generator picks a time signature and a step size from weighted pools and rolls every step, so bars of different lengths drift against the 4/4 of other tracks (IDM-style breaks and blips).

metersweighted time signatures, e.g. "4/4*3 7/8*2 5/8 9/16" (*n = weight)
divsweighted step sizes from 1/8 1/8T 1/16 1/16T 1/32 1/32T 1/64, e.g. "1/16*3 1/32"
notesweighted note pool, e.g. "C2*4 E2*2 C3" (on a sliced sampler each note is a slice)
modewhere hits fall: random (coin per step), euclid (spread evenly), or markov (a transition matrix decides notes and rests, below)
pickwhich note of the notes lane each hit plays: order (the next one, cycling), pingpong (back and forth), random (weighted by *n), walk (neighbouring notes; jump = chance of a leap). Per-note svel/slen (below) also apply.
density, downchance of a hit per step / on the bar's first step
ratchet, ratchetMaxchance a hit becomes a roll of 2…ratchetMax repeats
repeat, mutatechance to replay the previous bar, and the chance each of its steps is re-rolled
vel, len[min, max] velocity and length (in steps)
seed0 = a new take every play; any other integer replays the same take
matrixMarkov mode: the states are the notes in the pool plus a final rest. Either an array of rows (row = current state, column = next state, weights 0–1) or an object such as {"C2": {"E2": 1, "rest": 0.3}, "E2": {"C2": 1}, "rest": {"C2": 1}}. Up to 32 states; a note may appear more than once (each copy is its own state). Only marked cells (weight above 0) are ever taken; a row with nothing marked goes to rest. With down, a bar that would start on a rest starts on a note the row marks instead (never an unmarked one). A Markov bar is only replayed by repeat when the jump from its end back to its start is a marked cell, and mutate does not apply.
svel, slenoptional per-note (or per-Markov-state) velocity and length, arrays aligned with notes; null = use vel/len dice. Example: "svel": [1, null, 0.4].
sdurMarkov mode: how many steps each state (row) lasts before the chain moves on, one entry per state with rest last, e.g. [1, 2, 4, 1]. A state longer than 1 step plays its note for the whole time (its own slen, if set, wins; the len dice only apply to 1-step states) and spreads any ratchet roll across it; a longer rest row makes longer silences. A state can run on over the bar line. Default 1.

Dice settings can be automated and locked like any knob: track/gen/<pattern index>/density (also down ratchet ratchetMax repeat mutate jump velLo velHi lenLo lenHi).

notes list: {s: step (a fraction places the note off the grid: 3.37 lands 37% of the way into step 4, unaffected by swing), n: note, v: velocity 0–1, l: length in steps (fractions OK), p: chance 0–1, c: trig condition (below), g: 1 (slide)}.

Trig conditions (c on a note or a Euclidean row) decide when a step plays: "A:B" = on loop A of every B ("2:4"); "1st" = the first loop only; "fill" = only while the player holds the Fill button; "pre" = only if the previous condition on this track was true; "nei" = only if the last condition on the track above was true; "25%" = a chance. ! in front inverts any of them ("!fill", "!1:2"). Use pairs like "1:2" then "!pre" for call and answer, and "fill" rolls with "!fill" grooves for live fills.

More sequencers

Besides steps, notes and gen, a pattern can be one of five machines. Each is a key on the pattern object; div sets the step size for all but mini. Every kind works under the track's chords mode (an arpeggio clocked by Life cells, a Turing bass on chord roots…) and on modulation lanes.

Velocity reaches every instrument: the out module's vel (default 0.7) sets how much it changes the loudness, with velocity 0.8 (the default of x steps and most machines) always at the level set, 1 about 2 dB louder, a ghost note (0.45) about 5 dB softer and 0.35 about 6 dB softer. Set vel: 1 for more contrast, 0 to ignore velocity. Each machine below has its own way to set velocity.

Euclidean rows: {"euclid": [{n, k, steps, rot, v, acc, l, p, c}]} or the short form {"euclid": "C1 4/16, D1 3/8+2"} (note hits/steps+rotation; the note can be left out). Each row spreads k hits as evenly as possible over its own steps (1–64), rotated right by rot; v is the row's velocity and acc accents that many of its hits (spread evenly among them, the first hit first) at full velocity; rows of different lengths drift (3/8 against 2/5 lines up every 40 steps). Up to 16 rows. Live knobs: track/pat/<i>/hits/<row>, …/rot/<row> and …/acc/<row>.

Turing machine: {"turing": {bits, change, notes, density, l, vel, seed, reg}}. A loop of bits (2–16) shifts one step at a time; the newest 8 bits pick a note from notes (low values = the first notes) and, by a fixed hash, whether it plays (density 0–1) and its velocity (vel [min, max]). change 0 = the loop repeats exactly every bits steps; 0.05–0.3 = it slowly mutates; 1 = all random. seed makes the starting loop repeatable; reg (an integer) is a kept loop that always starts the same. l = note length in steps. Live knobs: track/pat/<i>/change, density, l.

Pattern language: {"mini": "bd*2 [~ sd] hh(3,8)", "bars": 1} or {"mini": {code, bars, seed}}, mini-notation in the style of TidalCycles/Strudel. One cycle lasts bars bars (0.25–16) and is split evenly between its words. [a b] = a group in one slot; ~ or - = rest; a*2 / a/2 = faster / slower; <a b> = one per cycle; a!3 = repeat; a _ _ or a@3 = longer; a? / a?0.3 = sometimes dropped; a(3,8,2) = Euclidean (rotated left); [a, b] = together (chords, layers); [a | b] = one at random each cycle; {a b c}%4 = polymeter. Words: notes (c3 eb4 f#2; a letter alone = the track's octave), whole numbers = degrees of the song scale (0 = the key's root at or below the track's note, negative = below), x X o = the track's note (normal, accent, ghost), drum names = General MIDI notes: bd kick sd sn snare rim rs cp clap hh ch hat oh lt mt ht cr cy crash rd ride cb cowbell tb sh. Randomness (?, |) is the same on every play; change seed for another take. Velocity: vel is a second line in the same notation, made of numbers 0–1, laid over the cycle (like Strudel's .velocity): {"mini": {"code": "hh*8", "vel": "[1 .5]*4"}} makes every other hat soft, "<.5 .7 .9 1>" swells over four cycles. Each note takes the value sounding at its start; X/o words scale it (×1.25, ×0.56); without a line, x = 0.8, X = 1, o = 0.45.

Cartesian (after the René): {"cart": {w, h, notes, gates, mode, x, y, xdir, ydir, skip, l, seed}}. A grid of w×h (1–8) cells in reading order; notes lists one note per cell (a shorter list repeats), gates one character per cell: x open, X accent, o ghost, . closed. mode: xy (X moves every x steps, Y every y steps, each in its direction fwd back pingpong random; the defaults read row by row, any other y drifts), snake (row by row, back and forth), walk (a random neighbour each step), random. skip: true jumps over closed cells. vels (optional) gives open cells their own velocity, one number 0–1 or null per cell (null = from the gate: X 1, x 0.8, o 0.45). Live knobs: l, x, y.

Cellular automata: {"cells": {rule, notes, steps, seed, every, max, fill, l, wrap, seed0}}. Life-like rules (life, highlife, seeds, daynight, maze, 2x2, morley, diamoeba, replicator, or any "B36/S23") run on a grid of rows = notes (lowest first) × columns = steps: the playhead plays each column's living cells, and every every passes the grid lives one generation. seed is the starting grid, one string per note row ("x..x...."). A number 0–255 is an elementary rule (30, 90, 110…): seed is then one string across the notes and every step is the next generation. vel = [cells that lived on, newborn cells] (default [0.7, 0.95], so new life is accented); max caps the notes per step; when everything dies or freezes, fill (0–1) reseeds that density at random (0 = let it end; seed0 makes that repeatable). Live knobs: fill max every l.

Chords and progressions

A progression is a list of chords: letter names (Am7 D9 Gmaj7 C/E) or Roman numerals in the song's key, which is the root of scale (ii7 V7 Imaj7; upper case = major, lower case = minor, b/# before the numeral move it, ° = diminished, ø = half-diminished, V7/V = the V7 of V). :n makes a chord last n units; % repeats the last chord; N.C. = no chord. Qualities: 5 6 7 9 11 13 69 M maj m min - dim ° o aug + sus2 sus4 sus m6 maj7 M7 Δ Δ7 ma7 m7 min7 -7 mmaj7 mMaj7 mM7 dim7 °7 o7 m7b5 ø ø7 aug7 +7 7#5 7sus4 7sus 9sus4 9sus 13sus 13sus4 add9 add2 madd9 maj9 M9 m9 m11 maj11 maj13 m13 7b9 7#9 7#11 7b13 7alt 6/9 m6/9 maj7#11 maj9#11 m9b5.

Put the song's progression in progression. A track follows it with "chords": {mode, prog, len, voicing, oct, inv, lead, strum, bass}. The modes are:

  • chord: every note any of its patterns plays (steps, piano roll, stochastic, Markov, keys) becomes the whole chord sounding now. The pattern gives the rhythm and the progression the harmony.
  • tones: white keys from C4 pick chord tones: C4 = root, D4 = 2nd tone, E4 = 3rd, and so on through the octaves. Melodies always fit.
  • snap: each note moves to the nearest chord tone.
  • bass: each note becomes the chord root (or slash bass) nearest the written note.
  • arp: an arpeggiator. Each note the patterns play starts an arpeggio of the chord sounding now, at rate (1/4 1/8 1/8T 1/16 1/16T 1/32), for as long as the note lasts; rate: "hit" makes every note the next step instead, so any sequencer clocks it. order: up down updown downup converge diverge random played; range 1–4 octaves; gate 0.05–1 of each step. With no progression it arpeggiates the notes the pattern plays together (or the keys held).
  • off: notes as written.

Give a track its own prog (and len) to leave the song progression. voicing is close, open, drop2 or spread, with oct 0–8 (4 = around middle C) and inv 0–3 for the first inversion. lead (default true) voice-leads each chord to the nearest inversion. strum is 0–500 ms, and bass: true adds the root below. Sub-patches (reusable abstractions)

Build a patch once and use it like a single module, in any instrument, custom effect or other sub-patch (up to 8 levels deep). Define it in the song's patches library. Inside it, every inlet module becomes an input socket of the box and every outlet an output socket, named after the module. controls puts knobs on the box: each one drives one or more inner knobs, given as "node.param"; inner sub-patch knobs count too. Shorthands: a string, an array of strings, or {to, min, max, label}.

"patches": {
  "fmop": { "label": "FM operator",
    "nodes": { "pm": {"type": "inlet"}, "osc": {"type": "osc", "wave": "sine"}, "env": {"type": "env", "d": 0.5, "s": 0.4},
               "vca": {"type": "vca"}, "out": {"type": "outlet"} },
    "wires": ["pm -> osc.pm", "osc -> vca", "env -> vca.cv", "vca -> out"],
    "controls": { "ratio": "osc.ratio", "level": {"to": "vca.gain", "max": 2}, "decay": "env.d" } } },
"inst": { "nodes": { "mod": {"type": "sub", "patch": "fmop", "ratio": 3, "level": 1.2},
                     "car": {"type": "sub", "patch": "fmop", "ratio": 1, "decay": 1.5}, "out": {"type": "out"} },
          "wires": ["mod.out -> car.pm", "car.out -> out"] }

Every use shares the inside: edit it once and all uses change. Each use keeps its own knob values. Paths reach a box knob as track/inst/mod/ratio, and any inner module as track/inst/mod/osc/fine. This works for lanes, step locks, scenes and MIDI. Built-in sub-patches you can use by name without defining them: fmop (FM operator), amp (Amp envelope), filterenv (Filter + envelope), echo (Filtered echo), stage (Phaser stage pair). The page copies them into the song's library. You can also write a definition inline as "patch": {…}; it moves into the library under its label.

Scenes

{name, bars, play:{trackId: "A"|0|...}, set:{path: value}, ramp:{path: [from, to]}}. Tracks left out of play are silent. set applies when the scene starts; ramp moves a value smoothly across the scene (filter sweeps, delay throws). In Song mode the scenes play in order and loop.

Automation

Recorded parameter moves, from the ● Rec button or written by hand. A scene keeps them in auto: {path: [[beat, value], …]}, with beats counted from the start of the scene (0 up to bars × 4) and looping with it. Numbers glide in a straight line from point to point, and from the last point round to the first. Switches (true/false, …/mute, …/on), menu choices (text) and pattern launches jump and hold. A song without scenes keeps them at the top level in auto, looping every autoBars bars (1–64; by default the longest pattern). autoBase: {path: value} is what each automated parameter plays where it is not automated (other scenes, and after stop). Duplicating a scene copies its automation.

"scenes": [{ "name": "Build", "bars": 4, "play": { "bass": "A" },
  "auto": { "bass/fx/0/cut": [[0, 300], [12, 2400], [15.5, 600]],
            "hat/mix/mute": [[0, false], [14, true]],
            "bass/play": [[0, -1], [8, 1]] } }],
"autoBase": { "bass/fx/0/cut": 900, "hat/mix/mute": false, "bass/play": -1 }

Any path below can be automated. track/play is a pattern launch: the index of the pattern to play from that point on (-1 = the scene's own). Use ramp for one simple sweep and auto for curves, steps and recorded takes.

Paths: bpm, swing, midi/cc/ch/cc, track/mix/vol|pan|mute|solo, track/play (pattern launch, for automation), track/send/A, track/inst/node/param, track/fx/index/param, track/fx/index/node/param (custom effect), track/fx/index/on, track/gen/index/density (dice), track/pat/index/change (Turing, Cartesian and cells knobs), track/pat/index/hits/row, …/rot/row, …/acc/row (Euclidean rows); inside sub-patches track/inst/sub/knob or track/inst/sub/inner/param. Returns and master use their ids (A, B, master) as the track.
